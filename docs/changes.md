# Changes in this fork

What this fork changed on top of the reconstruction it was forked from
([opencod2/opencod2](https://github.com/opencod2/opencod2)), by area. The
per-stage history is in [ai/PROJECT_MEMORY.md](ai/PROJECT_MEMORY.md).

- **Builds that work again:** the Linux and MinGW builds, broken since the original was built only with MSVC, build again; `scripts/build_check.py` builds Linux and MinGW (the dedicated server and, with SDL2, the client), as 1.3 and as 1.0, in one go.
- **Compiled as C++:** on Linux and MinGW the whole engine compiles as C++ (gnu++17), with the shared headers made valid C++, without changing what it does; checks guard the C names the data blobs rely on and the structure layouts of the original binary.
- **CoD2rev-Plus's script VM:** the GSC virtual machine is CoD2rev-Plus's, copied unchanged into `src/script`, with a generated C/C++ bridge. The server now holds two players, disconnects, reconnects and `clientkick`, where the reconstructed VM crashed as soon as the second player joined.
- **CoD2rev-Plus's server:** the dedicated server is built with CoD2rev-Plus's server, copied unchanged into `src/server`, with a generated bridge in which every call between the two is checked against the engine's ABI. The local games of the Linux and Windows (MinGW) clients run on it too, and the whole client traces with its collision: a client hosts a game and others join it. With it the server refuses to send the stock and server-only `.iwd` files. Its game and bgame (`src/game`, `src/bgame`) come with it, and with them `addip` and the rotation of `games_mp.log`; in the client, cgame keeps the engine's bgame (`src/PC/bgame`), whose globals take the `eng_` prefix, and which now predicts the player's moves, mantles and weapon with CoD2rev-Plus's code: in the same moves it now mispredicts (snaps back) about an eighth as often. Since then the dedicated server also runs on its core: `universal`, `qcommon` and the platform code (`src/universal`, `src/qcommon`, `src/unix`, `src/win32`), which bring the console log's rotation and timestamps, `net_strictPort` and its crash report. With its xanim (`src/xanim`, upstream's reviewed version) too, everything the dedicated server runs is CoD2rev-Plus's code.
- **CoD2rev-Plus's libcod:** the dedicated server is built with libcod, copied unchanged into `src/libcod` with the modules CoD2rev-Plus turns on (all but MySQL): its script functions, the bots, `sv_master1` to `sv_master5`, HTTP and WebSocket (Mbed TLS), SQLite and JSON. It passes CoD2rev-Plus's smoke, bots and HTTP tests in 1.3 and 1.0; the client's local games have it too, on its local server (Linux and Windows): the bots test passes there as well, and the HTTP test on Linux.
- **A dedicated server without the client's libraries:** on Linux `cod2_lnxded` needs only libc, libm, libz and libstdc++, not GL, X11, SDL2 or curl.
- **The Windows client's real lighting:** the Windows client draws with Direct3D 9 and compiles the game's own shaders with the system's d3dx9, as the original renderer does, instead of the stand-in shaders of the Mac port's GL layer (a white world and sky). The sun, the lightmaps, the models' lighting and the sky look as in the original: under Wine, next to the original `CoD2MP_s.exe` on the same spots, the two draw nearly the same picture. On the way, several of the renderer's tables that the reconstruction had left zero were filled from the original (the view weapon and players drew black, static models too), the textures load at full size again, and `r_aspectRatio` and full screen work.
- **The Linux client's real lighting:** `cod2_linux_vk` (`-DCOD2_LINUX_DXVK=ON`) runs the same Direct3D 9 path on DXVK native, over Vulkan, and compiles the game's shaders with vkd3d-shader ([ADR 0009](architecture/adr/0009-linux-client-on-dxvk.md)); `cod2_linux` keeps the GL device.
- **Fixes:** the server answered on the wrong port, saw no `.iwd` on Windows drives under WSL, and crashed on any kick; it announced protocol 118 in the 1.0 build; the C++ Linux build stays on glibc 2.34; `getAnimLength` and three other animation builtins no longer crash the server. The fourth or fifth map load crashed the server: the animation script grew with each map, and the error it raised from rcon corrupted the stack. The 1.0 server wrote over its own configstrings and no 1.0 client could join. Fragmented messages used the wrong offsets in both versions, and the port of a network address was where Quake III keeps it, not where CoD2 does. The `.iwd` files in the server's own folder were not searched, and the builtins that take a player did not see one with CoD2rev-Plus's VM. Entities were linked into the world's sectors under the wrong number, so unlinking some of them crashed and traces tested the previous entity. In the client, every entity clipped as a box was left out of the world's sectors and the box test missed the segments that crossed it, so bullets went through the players of a local game; and since an upstream change for x64, no animation of more than one frame played on 32 bits, which left the players and the first-person weapon in a broken pose. The client crashed when it saw a player die, and its movement prediction could overrun its stack against walls; it sent a jump, a stance or a weapon change one command late and truncated the velocity it predicts; the MG42's anims, the UI's fill and text widths and a dozen other engine calls passed arguments or read results of another type than the function's, and effects played along a direction got a broken axis. No effect was drawn at all (impacts, explosions, the maps' smoke): the effects code read its flags, curve scales, colors and velocities otherwise than the original binary, scheduled delayed parts for a time that never came, left every particle at the world's origin with no second radius, and nothing drew them. A changed configstring dropped the client and the scoreboard stayed empty (the server commands' letters had other meanings), a thrown grenade hung in the air (no entity moved between its events), and snow fell only indoors (the outdoor map was upside down). On the server a player's eye, where shots start, never bobbed while walking, and would have bobbed in the air; it now bobs as 1.3's (fixed in CoD2rev-Plus). Other players' animation followed a reconstruction that differed from 1.3: the animation rate went back to normal speed every frame between snapshots, turrets were tested with the wrong flags, the torso turned with the head too late or too early while aiming or firing, and a stance change blended in for the wrong time; it now follows CoD2rev-Plus and 1.3.
- **Tests:** CoD2rev-Plus's smoke test, unchanged, against this server, with the list of checks it does not pass yet; tests for two players, map loads, a drop error from rcon and the animation builtins; and checks for structure layouts, C names, the ABI of the bridge and the files copied from CoD2rev-Plus. Tests fire level and down at a player and check that each shot lands on the upper body or on the legs, and that a knife and an explosion reach a player, on the dedicated server and in a local game.
