Исходный код движка **Call of Duty 2**, полученный методом обратной разработки: многопользовательский клиент и выделенный сервер для Linux и Windows.

Этот репозиторий — форк [opencod2/opencod2](https://github.com/opencod2/opencod2), где и была проделана реконструкция движка. В нём также есть изменения из [Sipex18/opencod2-web](https://github.com/Sipex18/opencod2-web). Здесь добавлены только изменения, описанные в разделе [Изменения в этом форке](#изменения-в-этом-форке). Его цель — стать одним репозиторием с клиентом и выделенным сервером, перенося сюда сервер [CoD2rev-Plus](https://github.com/JotaJazz/CoD2rev-Plus) модуль за модулем. В Linux это сделано: выделенный сервер полностью работает на коде CoD2rev-Plus, а локальные игры клиента — на его сервере.

> [!WARNING]
> **Работа в процессе — это пока не работает полностью.** Клиент загружается до главного меню и создаёт локальные игры, к которым подключаются другие клиенты, а выделенный сервер, теперь из CoD2rev-Plus, загружает карты и держит игроков в 1.0 и 1.3, но ожидайте падений, недостающих функций и неработающих возможностей. Проект выложен для любопытных и для совместной работы, а не как законченный или пригодный для игры порт.

> [!IMPORTANT]
> **Игровой контент не включён — нужны собственные данные.** Этот репозиторий содержит только исходный код: никаких исполняемых файлов, архивов, карт, моделей, текстур, звуков или скриптов. Чтобы что-либо запустить, нужно предоставить файлы данных из копии игры, которой **вы законно владеете**.

## Изменения в этом форке

- **Сборки снова работают:** сборки для Linux и MinGW, сломанные с тех пор, как оригинал собирался только MSVC, снова собираются; `scripts/build_check.py` собирает Linux и MinGW (выделенный сервер и, с SDL2, клиент), как 1.3 и как 1.0, за один раз.
- **Компиляция как C++:** в Linux и MinGW весь движок компилируется как C++ (gnu++17), общие заголовки сделаны корректным C++, без изменения поведения; проверки охраняют C-имена, на которые опираются блоки данных, и раскладку структур оригинального бинарного файла.
- **Виртуальная машина скриптов CoD2rev-Plus:** виртуальная машина GSC взята из CoD2rev-Plus, скопирована без изменений в `src/script`, со сгенерированным мостом C/C++. Сервер теперь держит двух игроков, отключения, переподключения и `clientkick`, тогда как реконструированная виртуальная машина падала, как только подключался второй игрок.
- **Сервер CoD2rev-Plus:** выделенный сервер собирается с сервером CoD2rev-Plus, скопированным без изменений в `src/server`, со сгенерированным мостом, в котором каждый вызов между ними проверяется по ABI движка. Локальные игры клиентов для Linux и Windows (MinGW) тоже работают на нём, а весь клиент использует его столкновения: один клиент создаёт игру, другие подключаются. С ним сервер отказывается отправлять стандартные и предназначенные только для сервера файлы `.iwd`. Вместе с ним пришли его game и bgame (`src/game`, `src/bgame`), а с ними `addip` и ротация `games_mp.log`; в клиенте cgame сохраняет bgame движка (`src/PC/bgame`), чьи глобальные переменные получают префикс `eng_` и который теперь предсказывает движения, перелезание и оружие игрока кодом CoD2rev-Plus: при тех же движениях предсказание теперь ошибается (откаты) примерно в восемь раз реже. С тех пор выделенный сервер работает и на его ядре: `universal`, `qcommon` и коде платформы (`src/universal`, `src/qcommon`, `src/unix`, `src/win32`), которые приносят ротацию и метки времени журнала консоли, `net_strictPort` и отчёт о падениях. Вместе с его xanim (`src/xanim`) всё, что выполняет выделенный сервер, — это код CoD2rev-Plus.
- **libcod из CoD2rev-Plus:** выделенный сервер собирается с libcod, скопированной без изменений в `src/libcod`, с модулями, которые включает CoD2rev-Plus (все, кроме MySQL): её скриптовые функции, боты, `sv_master1`–`sv_master5`, HTTP и WebSocket (Mbed TLS), SQLite и JSON. Он проходит smoke-тест, тест ботов и тест HTTP из CoD2rev-Plus в 1.3 и 1.0; в клиенте её пока нет.
- **Выделенный сервер без библиотек клиента:** в Linux `cod2_lnxded` нужны только libc, libm, libz и libstdc++, а не GL, X11, SDL2 или curl.
- **Исправления:** сервер отвечал не на том порту, не видел `.iwd` на дисках Windows под WSL и падал при любом кике; в сборке 1.0 он сообщал протокол 118; сборка C++ для Linux остаётся на glibc 2.34; `getAnimLength` и три другие встроенные функции анимации больше не роняют сервер. Четвёртая или пятая загрузка карты роняла сервер: скрипт анимаций рос с каждой картой, а ошибка, которую он вызывал из rcon, портила стек. Сервер 1.0 перезаписывал собственные configstrings, и ни один клиент 1.0 не мог подключиться. Фрагментированные сообщения использовали неверные смещения в обеих версиях, а порт сетевого адреса находился там, где его хранит Quake III, а не там, где CoD2. Файлы `.iwd` в собственной папке сервера не искались, а встроенные функции, принимающие игрока, не видели его с виртуальной машиной CoD2rev-Plus. Сущности привязывались к секторам мира под неверным номером, поэтому отвязка некоторых из них роняла сервер, а трассировки проверяли предыдущую сущность. В клиенте каждая сущность, обрезаемая как бокс, выпадала из секторов мира, а проверка бокса пропускала пересекающие его отрезки, поэтому в локальной игре пули проходили сквозь игроков; а после изменения upstream для x64 на 32 битах не проигрывалась ни одна анимация длиннее одного кадра, и игроки и оружие от первого лица оставались в сломанной позе. Клиент падал, когда видел смерть игрока, а предсказание движения могло переполнить стек у стен; он отправлял прыжок, смену стойки или оружия на одну команду позже и отбрасывал дробную часть предсказанной скорости; анимации MG42, заливка и ширина текста в UI и ещё десяток вызовов движка передавали аргументы или читали результаты другого типа, чем у функции, а эффекты с направлением получали неверные оси. Эффекты не рисовались вовсе (попадания, взрывы, дым на картах): код эффектов читал свои флаги, масштабы кривых, цвета и скорости иначе, чем оригинальный бинарник, откладывал части с задержкой на время, которое не наступало, оставлял каждую частицу в начале координат мира без второго радиуса, и ничто их не рисовало.
- **Тесты:** smoke-тест CoD2rev-Plus, без изменений, против этого сервера, со списком проверок, которые он пока не проходит; тесты с двумя игроками, загрузок карт, ошибки drop из rcon и встроенных функций анимации; а также проверки раскладки структур, C-имён, ABI моста и файлов, скопированных из CoD2rev-Plus. Тесты стреляют в игрока горизонтально и вниз и проверяют, что каждый выстрел попадает в верхнюю часть тела или в ноги, а нож и взрыв достают игрока, на выделенном сервере и в локальной игре.

Каждое изменение подробно описано в [docs/CHANGES.md](docs/CHANGES.md) (на английском).

## Версии игры

- **Версия выбирается при сборке.** По умолчанию движок собирается как 1.3 (протокол 118); с `-DCOD2_FEATURE_CFLAGS=-DCOD2_PATCH_10` он собирается как 1.0 (протокол 115).
- **Оба выделенных сервера работают для тестов:** в 1.3 и в 1.0 сервер загружает, меняет и перезапускает карты, отвечает на `getinfo`, `getstatus` и rcon и держит двух игроков, которые входят, выходят, возвращаются и получают кик.
- **Локальные игры работают для тестов:** в 1.3 и в 1.0 клиент создаёт игру на сервере CoD2rev-Plus, другой клиент подключается, и оба остаются после `map_restart` и смены карты (`scripts/listen_test.py`, с вашим CD-ключом). Выстрел попадает в ту часть тела, в которую направлен (`scripts/hit_location_test.py`).
- **То, что есть в CoD2rev-Plus в libcod, здесь пока нет:** его функции скриптов, боты и `sv_master1`…`sv_master5`, поэтому сервер отправляет heartbeat только на мастер-сервер Activision.

## Сборка

Все цели собираются с помощью **CMake (≥ 3.16)**, каждая вне дерева исходников, в собственную папку.

### Linux

Движок — это 32-битный бинарный файл x86. В 64-битной системе Debian или Ubuntu нужны 32-битная архитектура и библиотеки:

```sh
sudo dpkg --add-architecture i386 && sudo apt update
sudo apt install build-essential gcc-multilib g++-multilib cmake \
     libsdl2-dev:i386 libgl1-mesa-dev:i386 libx11-dev:i386 \
     libcurl4-openssl-dev:i386 zlib1g-dev:i386 libstdc++6:i386
```

```sh
cmake -S . -B build-native
cmake --build build-native -j
# -> build-native/cod2_linux    (client)
# -> build-native/cod2_lnxded   (dedicated server)
```

Библиотеки клиента нужны для сборки обоих, но `cod2_lnxded` запускается только с 32-битными libc, libm, libz и libstdc++.

### Windows (кросс-компиляция из Linux с помощью MinGW)

Нужны 32-битные компиляторы MinGW-w64 (`g++-mingw-w64-i686`) и статическая zlib для MinGW (`libz-mingw-w64-dev`).

```sh
cmake -S . -B build-win32 -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-mingw32.cmake
cmake --build build-win32 -j
# -> build-win32/cod2_win32_ded.exe   (dedicated server)
```

Добавьте `-DCOD2_WIN32_CLIENT=ON` для клиента SDL2/GL (статические библиотеки SDL2 нужно положить в `src/win32/sdl2/lib/`; выделенному серверу они не нужны). Как и Linux-клиент, он запускает локальные игры на сервере, game и bgame CoD2rev-Plus и использует его столкновения. Без Windows `scripts/portable_wine.sh DIR` устанавливает 32-битный Wine без root (Debian или Ubuntu с включённой архитектурой i386) и создаёт `DIR/wine.sh` для запуска; `COD2_CONSOLE_STDOUT=1` копирует консоль в stdout, а `scripts/listen_test.py --host-binary cod2_win32.exe --host-wine DIR/wine.sh` заставляет его создать игру, к которой подключается Linux-клиент.

### Windows (MSVC, нативно)

Нативная сборка полного клиента SDL2/GL с Visual Studio 2022 или новее и её набором инструментов **x86**. Настройте и соберите из командной строки "x86 Native Tools for VS":

```bat
cmake --preset msvc-client
cmake --build build/msvc --target cod2_win32
:: -> build/msvc/cod2_win32.exe

cmake --preset msvc-client-release
cmake --build build/msvc-release --target cod2_win32
:: -> build/msvc-release/cod2_win32.exe   (/O2)
```

Эта сборка по-прежнему компилирует C и использует реконструированную виртуальную машину скриптов (`src/PC/script`). SDL2 предоставляете вы: положите 32-битный пакет разработки SDL2 для MSVC в `third_party/SDL2-<version>/` и скопируйте `SDL2.dll` рядом с исполняемым файлом. С `-DCOD2_SDL2_STATIC=ON` она компонует статическую SDL2, собранную вами (`SDL2-static.lib`, в той же конфигурации, что и движок), и статическую среду выполнения C в один исполняемый файл, которому не нужны DLL; собирайте SDL2 с `-DSDL_STATIC=ON -DSDL_SHARED=OFF -DSDL_RENDER=OFF -DSDL_FORCE_STATIC_VCRT=ON`. Release применяет `/O2` к коду, верному декомпилятору, который проверен хуже, чем сборка Debug: если что-то ведёт себя неправильно только в Release, подозревайте оптимизатор.

### Параметры CMake

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `COD2_CXX_ALL` | `ON` | Компилирует движок как C++ в Linux и MinGW. `OFF` собирает C. |
| `COD2_CXX_DIRS` | `""` | С `COD2_CXX_ALL=OFF` — модули или файлы `src/`, которые всё равно компилируются как C++. |
| `COD2_PLUS_SCRIPT` | `ON` | Виртуальная машина скриптов CoD2rev-Plus (`src/script`) в Linux и MinGW. `OFF` использует реконструированную (`src/PC/script`), как это делают MSVC, веб-сборка и x64. |
| `COD2_PLUS_SERVER` | `ON` | Сервер, game, bgame и ядро CoD2rev-Plus (`src/server`, `src/game`, `src/bgame`, `src/universal`, `src/qcommon`, `src/xanim`, `src/unix` или `src/win32`) в выделенном сервере, в Linux и MinGW; требует `COD2_PLUS_SCRIPT`. `OFF` использует реконструированные (`src/PC/server_mp`, `src/PC/game_mp`, `src/PC/bgame`). |
| `COD2_PLUS_CLIENT_SERVER` | `ON` | Сервер, game, bgame и столкновения CoD2rev-Plus для локальных игр клиента (Linux, и MinGW с `COD2_WIN32_CLIENT`), на ядре движка; требует `COD2_PLUS_SERVER`. `OFF` оставляет `src/PC/server_mp`, как пока делают MSVC, веб-сборка и x64. |
| `COD2_PLUS_LIBCOD` | `ON` | libcod из CoD2rev-Plus (`src/libcod`) в выделенном сервере, с её модулями, кроме MySQL; требует `COD2_PLUS_SERVER`. Клиент собирается без неё. |
| `COD2_FEATURE_CFLAGS` | `""` | Переключатели возможностей; `-DCOD2_PATCH_10` собирает версию 1.0. |
| `COD2_WIN32_CLIENT` | `OFF` | MinGW: клиент SDL2/GL вместо выделенного сервера. |
| `COD2_WIN_MSVC` | `OFF` | Нативная сборка MSVC (задаётся пресетами `msvc-client`). |
| `COD2_SDL2_STATIC` | `OFF` | MSVC: один автономный исполняемый файл со статическими SDL2 и средой выполнения C. |
| `COD2_DEBUG` | `OFF` | `-O0` и без усиления защиты, для отладки. |
| `COD2_X64` | `OFF` | Цель x86_64; порт в процессе, который компилируется, но пока не запускается. |

Есть также сборка WebAssembly (`emcmake cmake -S . -B build/web`, с Emscripten SDK), описанная в начале `CMakeLists.txt`.

## Запуск

Движку нужны файлы оригинальной игры (папка `main` с файлами `.iwd`), которых в этом репозитории нет. Нужна собственная копия Call of Duty 2.

```sh
./build-native/cod2_linux +set fs_basepath /path/to/CoD2
./build-native/cod2_lnxded +set fs_basepath /path/to/CoD2 +set dedicated 1 +map mp_toujane
```

В Windows:

```bat
build\msvc\cod2_win32.exe +set fs_basepath "C:\path\to\CoD2"
build-win32\cod2_win32_ded.exe +set fs_basepath "C:\path\to\CoD2" +set dedicated 1 +map mp_toujane
```

`dedicated 1` оставляет сервер в локальной сети; это тестовый сервер, а не сервер для публичного списка — пока.

## Тесты

Проверкам нужна сборка, а тем, которые запускают сервер, — папка игры с оригинальными файлами `.iwd`. Они запускают сервер в режиме LAN с временной домашней папкой, поэтому папка игры только читается.

```bash
python3 scripts/build_check.py all                      # linux (1.3), linux-10 (1.0) and mingw into build/check-*/
python3 scripts/check_c_linkage.py build/check-linux    # no unexpected C++ names in the engine
python3 scripts/layout_parity.py                        # types shared with CoD2rev-Plus's VM lay out alike
python3 scripts/check_c_decls.py build/check-linux     # каждый вызов движка совпадает с типами своего определения
python3 scripts/check_var_sizes.py build/check-linux    # ни одна глобальная переменная не используется больше, чем определена
python3 scripts/opencod2_smoke.py /path/to/CoD2 --protocol 118
python3 scripts/two_players_test.py /path/to/CoD2 --protocol 118
python3 scripts/listen_test.py /path/to/CoD2 --protocol 118
python3 scripts/map_reload_test.py /path/to/CoD2 --protocol 118
python3 scripts/rcon_drop_test.py /path/to/CoD2 --protocol 118
python3 scripts/anim_builtins_test.py /path/to/CoD2 --protocol 118
python3 scripts/prediction_test.py /path/to/CoD2 --protocol 118
python3 scripts/fx_test.py /path/to/CoD2 --protocol 118
python3 scripts/bots_test.py /path/to/CoD2 --binary build/check-linux/cod2_lnxded
python3 scripts/http_test.py /path/to/CoD2 --binary build/check-linux/cod2_lnxded
python3 scripts/vendor_check.py /path/to/CoD2rev-Plus   # files copied from CoD2rev-Plus are unchanged
python3 -m unittest discover -s test
```

- `opencod2_smoke.py` запускает `scripts/smoke_test.py` из CoD2rev-Plus, без изменений, и сравнивает его ошибки с `test/smoke_expected_failures_<protocol>.txt`: проверками, которые этот сервер пока не проходит. Он завершается с ошибкой при новой ошибке и при проверке из списка, которая теперь проходит, поэтому списки только сокращаются. `--protocol 115` тестирует сборку 1.0. `--protocol 118 --binary build/check-mingw/cod2_win32_ded.exe --wine DIR/wine.sh` запускает его против выделенного сервера Windows под Wine (`scripts/portable_wine.sh`) со своим списком, `test/smoke_expected_failures_wine.txt`: под Wine сервер пишет только в своё окно, а сигнал не доходит до него как сигнал (SIGSEGV, отправленный через `kill`, игнорируется, SIGTERM сразу завершает его), поэтому отчёт о сбое, проверки SIGTERM и проверки его вывода там не выполняются (скрипт проверяет `net_strictPort` в его журнале консоли). Списки для Linux пусты: выделенный сервер проходит весь smoke-тест.
- `two_players_test.py` подключает двух клиентов на tdm, заставляет их отправлять команды, отключает одного и возвращает его, а другого кикает; сервер, с `developer 1`, чтобы ошибка скрипта останавливала карту, должен отвечать после каждого шага.
- `listen_test.py` запускает клиент, который создаёт игру, и второй, который к ней подключается, и проверяет их после `map_restart` и смены карты; нужен CD-ключ в `~/.cod2/preferences`.
- `map_reload_test.py` загружает карты через rcon, чередуя `map_restart` и `map` между двумя картами, и проверяет каждую загрузку; `rcon_drop_test.py` вызывает ошибку drop из rcon (`error drop`) и проверяет, что сервер продолжает работать.
- `anim_builtins_test.py` запускает `getAnimLength`, `animHasNotetrack`, `getMoveDelta` и `getAngleDelta` из скрипта уровня тестового мода.
- `prediction_test.py` считает ошибки предсказания настоящего клиента (с CD-ключом), который ходит, приседает, ложится, прыгает и стреляет; `--max-misses` задаёт допустимое число.
- `fx_test.py` заставляет настоящего клиента (с CD-ключом) проиграть перед собой спрайт, попадание пули и два взрыва и проверяет, что каждый меняет снимок экрана.
- `bots_test.py` и `http_test.py` взяты из CoD2rev-Plus без изменений и проверяют libcod: боты из `mods/bots` должны находить пути, сохранять и перечитывать свой граф и сражаться на настоящей карте; `httpFetch` и `webSocket*` должны работать с локальными серверами HTTP, HTTPS, WS и WSS (нужен `openssl`). Передайте им `--binary build/check-linux/cod2_lnxded`.
- `scripts/cxx_errors.py` подсчитывает ошибки C++ модуля (`--return-type` находит функции, возвращающие значение, которые могут завершиться без return, что в C++ является неопределённым поведением); `scripts/gen_script_bridge.py --module script|server` заново генерирует мост к виртуальной машине скриптов или к серверу, а `scripts/engine_abi.py --module server` записывает с помощью gdb ABI движка, по которому проверяется мост (`test/server_abi.txt`).

## Структура репозитория

| Путь | Содержимое |
| --- | --- |
| `src/PC` | Реконструированный движок: клиент (`client_mp`, `cgame_mp`, `ui_mp`), сервер (`server_mp`), игра (`game_mp`, `bgame`), рендерер (`gfx_d3d`), общий код (`qcommon`, `universal`), анимации (`xanim`) и реконструированная виртуальная машина скриптов (`script`). В Linux и в выделенном сервере MinGW `server_mp`, `game_mp`, `game` и ядро, которое заменяет CoD2rev-Plus, не используются (`test/plus_replaces.txt`); клиент MinGW не использует `server_mp`, `game_mp`, `game` и столкновения движка. |
| `src/Mac` | Платформенный слой порта для Mac, из которого получена реконструкция: OpenGL за интерфейсом Direct3D, ввод и звук. |
| `src/script` | Виртуальная машина скриптов CoD2rev-Plus, скопированная без изменений, с нужными ей заголовками в `src/qcommon`, `src/universal`, `src/game`, `src/bgame`, `src/server`, `src/xanim`, `src/zlib`, `src/misc` и `src/libcod`. |
| `src/server` | Сервер CoD2rev-Plus, скопированный без изменений; его использует выделенный сервер. |
| `src/game`, `src/bgame` | Game и bgame CoD2rev-Plus, скопированные без изменений; их использует выделенный сервер. |
| `src/universal`, `src/qcommon`, `src/xanim`, `src/unix`, `src/win32` | Ядро и код платформы CoD2rev-Plus, скопированные без изменений; на них работает выделенный сервер. `test/plus_replaces.txt` перечисляет исходники движка, которые они там заменяют. |
| `src/libcod`, `mods/bots` | libcod из CoD2rev-Plus и её библиотеки (yyjson, SQLite, Mbed TLS; её Speex не собирается, используется Speex движка) и её мод ботов, скопированные без изменений; их использует выделенный сервер. |
| `src/compat` | Мосты между C-именами движка и виртуальной машиной C++, сервером и ядром из CoD2rev-Plus; в основном сгенерированы. |
| `src/headers`, `src/imports` | Общие типы, смещения, проверенные по оригинальному бинарному файлу, и объявления импортируемых функций. |
| `src/blobs`, `build/native_gen`, `build/win_gen` | Данные, взятые из оригинального бинарного файла, которые движок всё ещё использует. |
| `src/unix`, `src/win32`, `src/stubs`, `src/web` | Код, зависящий от платформы, и заглушки. |
| `scripts` | Скрипты сборки и тестов, а также тестовый клиент из CoD2rev-Plus. |
| `test` | Юнит-тесты и списки, которые читают проверки. |
| `docs` | [CHANGES.md](docs/CHANGES.md) и баннер. |
